# apps/web

Vite + React SPA. TanStack Router (file-based, `src/routes`), TanStack Query, zustand, Tailwind
v4, shadcn-style components, dnd-kit + Motion for the board.

- **Routes:** `src/routeTree.gen.ts` is generated by the Vite plugin; never edit it. Routes under
  `src/routes/_authed/` require sign-in (UI convenience only; real enforcement is server-side).
- **Design tokens:** all colours, radii, card size, and z-index layers live in `src/styles.css`.
  Use the tokens (`bg-card`, `w-card-w`, …), not raw values. Reusable components go in
  `src/components/ui` (add more with `pnpm dlx shadcn@latest add <name>`).
- **Board:** `src/components/game/board.tsx` renders a `PlayerView` and reports intents via
  `onAction`. It must stay free of game rules so it serves both AI and online matches.
- **AI matches** run fully in the browser (`hooks/use-ai-match.ts`): local engine state, bot in
  a Web Worker. **Online matches** (`hooks/use-match-socket.ts`) only render server views.
- **Supabase client** (`lib/supabase.ts`) is null when env is unset; handle that case. Use it
  only for the user's own data. Cards come from `lib/catalog.ts` (server endpoint + IndexedDB),
  never from a `cards` query.
- **Tests:** unit tests next to the code (`*.test.tsx`, jsdom); browser tests in `e2e/`. Drag
  tests must use real mouse moves with steps (see `e2e/play-vs-ai.spec.ts`).
- **Env:** `.env.local` from `.env.example`. Only `VITE_`-prefixed values reach the browser;
  never put a service-role key here.
