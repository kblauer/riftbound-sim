# apps/server

Cloudflare Worker (Hono) plus the `Match` Durable Object (partyserver), one instance per match.

- **Entry:** `src/index.ts`. `/parties/*` is handled outside Hono because WebSocket upgrade
  responses must be returned untouched. Everything else goes through the Hono app.
- **Auth:** `src/auth.ts` verifies the Supabase JWT locally against the project's public keys
  (no Auth API call). The token arrives as `?token=`; the verified user id is passed to the
  Durable Object in the `x-riftbound-user-id` header. Never trust a user id from the client.
- **Match:** `src/match.ts`. State lives in memory and every accepted action is written to
  Durable Object storage; `onStart` rebuilds state from that log, so the object survives
  eviction. Each player is sent only their own `viewFor` view. One Supabase write, at match end.
- **Catalog:** `src/catalog.ts`. `/catalog/version` (5 min cache) and `/catalog/{version}`
  (immutable cache). These are the only code paths that read the `cards` table at runtime.
- **Env:** secrets (`SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`) go in `.dev.vars` locally and
  must point at the local Supabase stack. `ALLOWED_ORIGINS` is in `wrangler.jsonc`.
- **Types:** `worker-configuration.d.ts` is generated by `pnpm types` (git-ignored); rerun after
  changing `wrangler.jsonc`. Secrets are typed in `src/env.d.ts`.
- **Local gotchas:** stop `wrangler dev` by killing the whole process tree; a leftover instance
  keeps port 8787 and serves old env values. The local edge cache persists in
  `.wrangler/state/v3/cache`; delete it if a re-seeded catalog version does not show up.
- **Do not deploy** (`wrangler deploy`, `wrangler secret put`) unless the user asks.
- **Tests:** plain Vitest for pure modules. The Durable Object has no automated test yet; verify
  changes with `pnpm dev` and two WebSocket clients.
